# ADR-060 v1 范围冻结：不规划 v2

- 状态：**已接受**（2026-10-31，用户决定）
- 日期：2026-10-31
- 相关：README、MANUAL §20、ROADMAP、AGENTS §0、TASKS M6、DSH/HANDOFF、发布说明；
  ADR-003/009/010/012/016/045/052/055/057

## 背景

v1（0.1.0）已完成并发布准备就绪。此前的 `docs/ROADMAP.md` 记录了一组“未承诺的 v2 设想”
（SQLite/列式后端、公式列、多表关联/SQL、动态插件、macOS/Linux、自动更新、Excel、视觉回归等）。
用户 2026-10-31 明确：**不做 v2 设想**。

继续保留这些设想会带来错误预期：用户/维护者可能把 ROADMAP 当成排期，或在 issue/发布说明中
承诺未实现的能力。v1 的已知限制仍需如实记录，但不应附带“以后会做”的功能清单。

## 决定

1. **项目范围冻结在 v1（0.1.0）**：不规划、不承诺 v2 功能；不维护 v2 路线图。
2. `docs/ROADMAP.md` 改为**已知限制与维护范围**：只保留 v1 已知限制、明确非目标、决策入口；
   删除“v2 设想/候选”章节。
3. 同步删除/改写活文档中的 v2 承诺或指向：
   - README 文档索引/已知限制；
   - MANUAL §20（只保留已知限制，删除“v2 设想”）；
   - AGENTS/HANDOFF/TASKS/DSH/TESTPLAN/PROMPTS 中“走 v2 流程”的表述；
   - 发布说明中的“v2 方向”链接。
4. **保留**历史事实：旧 ADR/报告/CHANGELOG 中对当时 v2 讨论的引用不删除、不重写；
   以本 ADR 作为“不再规划 v2”的索引。
5. 后续只做**维护性变更**：bug 修复、安全修复、依赖升级、发布/文档修订；每项仍按 AGENTS
   的任务协议与 ADR/SPEC 流程执行。

## 代价

- 没有公开路线图，外部无法预期新功能；这是用户明确的选择。
- 已知限制仍然存在（无公式列/关联/SQL、仅 Windows、未签名等），只是不再承诺解除时间。
- 若未来重新考虑新功能，不能直接“复活”旧 ROADMAP 文本；应新写 ADR/需求与验收，重新评估
  数据格式、兼容性与维护成本。
- `SPEC §14.5 预留字段` 等**兼容性预留**继续保留（v1 忽略、不实现），但不代表 v2 计划。

## 影响

- 修改：`docs/ROADMAP.md`、`docs/MANUAL.md`、`README.md`、`AGENTS.md`、`docs/HANDOFF.md`、
  `docs/TASKS.md`、`docs/DSH.md`、`docs/TESTPLAN.md`、`docs/PROMPTS.md`、
  `docs/releases/0.1.0.md`、ADR 索引。
- 不改：代码、`formatVersion`、IPC、数据格式、安装包内容、依赖、测试基线。
- 历史 ADR/报告中的 v2 措辞保留；新文档不再承诺。

## 复核条件

- 只有用户明确要求“重新开启新功能规划”时，才新写 ADR 并定义范围/验收；不要自动恢复旧设想。
- 若只是维护（修 bug/安全/依赖/文档），按维护任务执行，不需要重新讨论 v2。
- 若发现“已知限制”描述不准确：修正文档事实，不等于规划新功能。
